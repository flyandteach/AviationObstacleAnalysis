# FAA Part 77 Obstacle Analyzer — Washington State

**Live site:** https://flyandteach.github.io/aviationobstacleanalysis/

Analyzes obstacle data against FAA Part 77 imaginary surfaces (14 CFR Part 77)
for Washington State public-use airports. Paste obstacle coordinates and
heights and it flags penetrations of the primary, approach, transitional,
horizontal, and conical surfaces, using FAA NASR runway-end data for
directionally correct approach/transitional geometry.

This runs entirely client-side — a static site with no backend, no
database, and no server to pay for. All airport/runway reference data is
bundled at build time; the analysis math runs in the browser.

## Local development

```bash
npm install
npm run dev       # dev server with hot reload
npm run build     # production build -> dist/
npm run preview   # serve the production build locally
npm run check     # typecheck
```

## Deployment (GitHub Pages, free)

A workflow at `.github/workflows/deploy.yml` builds the site and deploys it
to GitHub Pages automatically on every push to `main`.

One-time setup (only needs to be done once per repo):

1. On GitHub, go to **Settings → Pages**.
2. Under **Build and deployment → Source**, select **GitHub Actions**.
3. Push to `main` (or re-run the "Deploy to GitHub Pages" workflow from the
   **Actions** tab). The site will be published at
   `https://<your-github-username>.github.io/<repo-name>/`.

No further maintenance, servers, or payments required — GitHub Pages hosts
static sites for free.

## Updating the underlying airport/runway data

Source CSVs and NASR extracts live in `attached_assets/`. To regenerate the
bundled JSON data after updating a source file, run:

```bash
npm run prepare-data
```

This writes to `client/src/data/` and mirrors the filtering FAA NTAD /
approach-type / NASR data undergoes (Washington public-use, fixed-wing,
non-military airports).

## Architecture

- `client/` — React + Vite frontend (Tailwind, shadcn/ui, Leaflet map).
- `client/src/lib/` — obstacle parsing and Part 77 surface-penetration
  analysis (ported from what used to be an Express API route — see
  `replit.md` for the calculation history and FAA regulation references).
- `client/src/data/` — pre-filtered airport/runway JSON bundled at build
  time (generated by `scripts/prepare-static-data.mjs`).
